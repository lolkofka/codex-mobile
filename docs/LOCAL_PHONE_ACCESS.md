# Личная копия 0.6.6

Пакет `local.avr.codex.copy` обновляется своим существующим ключом из
`/data/adb/avr-codex-copy/signing`. Оригинальный пакет и данные не удаляются.

В истории работающий чат отмечен синим пульсирующим кружком. Жёлтый кружок
означает ожидание подтверждения. Настройки доступа находятся в «Настройки»
→ «Доступ к телефону»: независимые переключатели фоновых приложений и HTTP/HTTPS.

В уведомлениях о работе, результатах задач и временном HTTPS показана картинка
с логотипом приложения. Для строки состояния используется отдельный прозрачный
одноцветный значок, чтобы Android не превращал фон иконки в сплошной квадрат.

`tools/bin/codex-apps` использует отдельный виртуальный дисплей с собственным
фокусом и запретом перехвата основного фокуса. Он не запускает приложение на
дисплее 0 при ошибке. Глобальные аппаратные клавиши запрещены. Управление
доступно только root через локальный Unix-сокет; сетевого управляющего порта нет.
При отключении доступа, закрытии клиента или пяти минутах простоя дисплей удаляется.

`tools/bin/codex-traffic https PACKAGE SECONDS` работает только с выбранным UID,
на 10–120 секунд. Общие UID и сам Codex отклоняются. Требуются разрешённый
переключатель, свежий heartbeat и подтверждение видимого уведомления клиентом.
Сертификат доверяется только в mount namespace выбранного приложения. Основное
хранилище CA телефона не изменяется. Proxy слушает только 127.0.0.1; временное
правило отклоняет подключения других UID. Применяются только временные правила
для TCP/IPv4 портов 80/443; существующие TLS-соединения, IPv6 и QUIC могут
остаться вне захвата. Pinning и собственные хранилища доверия не обходятся.

Тайм-аут, стоп из уведомления, отзыв разрешения, исчезновение heartbeat или
аварийное завершение рабочего процесса вызывают очистку. Watchdog и отдельный
скрипт запуска Magisk выполняют только очистку, не начинают перехват. Удаляются
CA, закрытый ключ, bind mount, контейнер proxy и адресные правила netfilter.
Если очистку подтвердить нельзя, индикатор остаётся активным и новый сеанс
блокируется до успешной очистки. Аналитический JSONL остаётся только в защищённой
папке tools/traffic-reports; известные поля авторизации и паролей редактируются,
не-JSON тела и большие тела не сохраняются.

Для проверки использовано отдельное синтетическое приложение и example.com,
без пользовательских аккаунтов. Проверены реальный ответ HTTPS через временный
CA, обычная очистка и очистка после SIGKILL. Обновление самого клиента выполняется
только после записи завершения текущего ответа и периода простоя чатов.
