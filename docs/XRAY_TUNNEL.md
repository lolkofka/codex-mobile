# Xray in Codex Mobile · Copy

Open account → Xray · Подписки и хосты → Добавить подписку. HTTPS subscription URLs, plain or Base64 share-link lists (VLESS, VMess, Trojan, Shadowsocks) and Xray JSON proxy outbounds are supported. RAW/TCP, WebSocket, gRPC, HTTPUpgrade, XHTTP (including extra, padding, XMUX and split downloadSettings), TLS and REALITY are supported. Unsupported protocols/transports and insecure TLS produce an explicit error. No arbitrary subscription routing/listeners are imported. Subscription refresh is manual; invalid refresh retains the previous saved subscription. Exactly one host is selected, with no balancing or failover. If its identity disappears after refresh/deletion, strict mode blocks until the owner chooses a host again. First import selects the first host and enables strict mode; adding subsequent subscriptions keeps the chosen host.

When enabled, every connection from the local app-server through its authenticated HTTP_PROXY/HTTPS_PROXY/ALL_PROXY bridge goes through the bundled Xray and the selected outbound, including ChatGPT/OpenAI domains and subdomains without a domain allowlist. The bridge never tries Happ or a direct destination after an Xray error. Existing bridge connections close on configuration changes. Connections retry the same selected outbound. Selected-host errors are shown persistently in the app header and the Xray panel. An end-to-end TLS/HTTP check targets chatgpt.com without account credentials; an HTTP denial is reported separately from transport success.

This is an application tunnel, not an Android VPN. Other apps, external login browsers, SSH server connections and engines on remote PCs use their own networking. Subscription downloads use Android system networking, HTTPS-only with bounded redirects, timeouts and size; ChatGPT/OpenAI domains are disallowed as subscription sources. The unconfigured default retains the existing system/Happ behavior to keep the current client connected. Disabling Xray is an explicit native dialog; it is never an automatic recovery action.

The ARM64 executable is packaged as an extracted native library, verified at build time against android/native/xray.lock.json, and runs under the app UID. No root daemon, new system CA, SELinux change or LAN listener is needed. The local Xray listener binds 127.0.0.1, with a random per-process password. Xray receives config over stdin, never via argv or plaintext config files. Subscription URLs, keys and UUIDs are AES-GCM encrypted by an app-specific Android Keystore key. Only labels, endpoint metadata and opaque IDs enter the local UI; no credentials enter chats or model state. Core output is drained without logging. Closing the service terminates Xray; Android app cgroup cleanup handles process death.

Official upstream: https://github.com/XTLS/Xray-core/releases/tag/v26.11.9
Configuration: https://xtls.github.io/en/config/

XHTTP extra is decoded once from the share URI into an object, or preserved from Xray JSON. Nested download streams retain the selected profile’s transport settings and Android DNS resolution with original TLS server names. Routing/listeners, dialerProxy and TLS key-log paths from subscriptions are not imported. Invalid extra gives an explicit import error and leaves the saved subscription intact.
